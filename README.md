# bevy_playground

Экспериментальный cargo-воркспейс на [Bevy](https://bevy.org) 0.20 и [Avian3D](https://github.com/Jondolf/avian) 0.8.

Сейчас в нём две крейты:

| Крейта | Что это |
| --- | --- |
| `crates/portal_fps` | FPS-демка с механикой порталов из *Portal*: две глухие комнаты, попасть в соседнюю можно только через портал |
| `crates/bevy_playground` | Заготовка-песочница (`println!("Hello from bevy_playground!")`) |

---

## Быстрый старт

```bash
cargo run -p portal_fps          # dev-сборка
cargo run --release -p portal_fps # release, если нужен максимум FPS
```

Требуется Rust 1.97+ (воркспейс собран на 1.99.1) и Vulkan-совместимая видеокарта.

Первая сборка занимает несколько минут: профиль `[profile.dev.package."*"]` собирает все
зависимости с `opt-level = 3`, чтобы Bevy и физика не тормозили в dev-режиме. Дальше
пересборка после правок в наших крейтах занимает секунды — сам код воркспейса остаётся
неоптимизированным.

## Управление

| Клавиша | Действие |
| --- | --- |
| `W` `A` `S` `D` | движение |
| мышь | обзор (yaw — тело, pitch — камера) |
| `Shift` | бег |
| `Space` | прыжок |
| `R` | рестарт (телепорт на точку спавна) |
| `Esc` | отпустить курсор |
| клик ЛКМ | захватить курсор обратно |

Курсор захватывается только по клику — при запуске он свободен.

## Что происходит на экране

- Две комнаты, разделённые сплошной стеной. Левая — тёплая (оранжевая), правая — холодная (синяя).
  Это сделано намеренно: по цвету сразу понятно, в какую комнату ты смотришь через портал.
- В каждой комнате портал: оранжевая рамка в комнате A, голубая в комнате B.
- Сквозь портал видно соседнюю комнату в реальном времени — со параллаксом, колонной и лестницей.
  Это настоящий рендер вторым проходом, а не картинка.
- В правом верхнем углу — сглаженные FPS/время кадра и график времени кадра за последние
  ~2 секунды. Цвет столбиков: зелёный ≤ 16.7 ms (60 FPS), жёлтый до 33 ms, красный хуже.
- В левом верхнем углу — счётчик переходов через портал.
- На полу лежат ящики — просто чтобы было видно, что физика живая.

## Как устроены порталы

### 1. Картинка

Для каждого портала создаётся отдельная камера, которая рендерит сцену в текстуру
(`Image::new_target_texture`, формат `Rgba16Float`), и плоскость-экран с этим изображением.

Виртуальная камера ставится туда, где оказалась бы камера игрока, если бы он уже прошёл
через портал:

```text
V = T_dest · RotY(180°) · T_src⁻¹ · C
```

где `C` — трансформ камеры игрока, `T_src` / `T_dest` — трансформы порталов
(локальная `+Z` — внешняя нормаль). Поворот на 180° нужен потому, что порталы смотрят
в противоположные стороны.

Косая плоскость отсечения (`PerspectiveProjection::near_clip_plane`) проходит через
плоскость портала-приёмника: она отрезает стену, в которую вмонтирован портал, иначе
в отражении была бы видна её изнанка.

Шейдер `assets/shaders/portal.wesl` сэмплит текстуру **в экранных координатах**
(`input.position.xy / textureDimensions`), а не по UV. Поэтому render target обязан
совпадать по размеру с окном — при ресайзе текстуры пересоздаются.

### 2. Телепорт

Переход использует ту же функцию `portal_map()`, что и камера, — картинка и физика
не могут разойтись. Игрок телепортируется, когда одновременно:

- он перед плоскостью портала (`local.z > 0`) ближе `TELEPORT_DISTANCE`;
- попал в прямоугольник портала;
- движется **в** портал (`velocity · normal < 0`).

Позиция отображается через ту же матрицу, затем выталкивается вперёд на
`EXIT_CLEARANCE`, чтобы не застрять в стене. Yaw поворачивается вместе с порталом,
pitch остаётся как был. После перехода на `TELEPORT_COOLDOWN` секунд срабатывание
блокируется — иначе можно было бы «застрять» между двумя порталами.

### 3. Слои рендера

| Слой | Что на нём | Кто видит |
| --- | --- | --- |
| `WORLD_LAYER` (0) | весь уровень, свет | камера игрока **и** портальные камеры |
| `PORTAL_LAYER` (1) | экраны порталов | только камера игрока |

Портальные камеры не видят экраны — поэтому нельзя увидеть портал в портале. Это
осознанный компромисс: рекурсия требует отдельного прохода на каждый уровень глубины
и здесь не реализована.

Портальные камеры рендерятся с `Tonemapping::None` и `DebandDither::Disabled` —
тонмапит только камера игрока, иначе картинка внутри портала была бы тонмапнута дважды.

## Структура крейты `portal_fps`

```text
crates/portal_fps/
├── Cargo.toml
├── assets/shaders/portal.wesl   # screen-space сэмплинг render target
└── src/
    ├── main.rs      # плагины, окно, путь к ассетам, захват курсора, FALL_LIMIT
    ├── world.rs     # уровень: комнаты, стена, порталы, свет, слои рендера
    ├── physics.rs   # Player / MoveInput / Look, move_and_slide, гравитация, прыжок
    ├── player.rs    # камера игрока, mouse look, ввод, респавн
    ├── portal.rs    # материал+шейдер, виртуальные камеры, portal_map(), телепорт, ресайз
    └── ui.rs        # прицел, подсказка, счётчик переходов, FPS и график кадра
```

Порядок систем по кадрам:

- `FixedUpdate`: `gather_input` → `apply_movement` → `update_grounded` → `move_player`
- `Update`: mouse look, телепорт, HUD, респавн
- `PostUpdate` (после распространения трансформов): расстановка портальных камер и
  обработка ресайза окна

## Настройка

Почти всё вынесено в константы в начале файлов.

**Уровень** — `src/world.rs`:

| Константа | Значение | Смысл |
| --- | --- | --- |
| `ROOM_WIDTH` / `ROOM_HALF_DEPTH` / `ROOM_HEIGHT` | 16 / 8 / 4 | размеры комнат |
| `WALL_THICKNESS` | 0.2 | толщина разделяющей стены |
| `PORTAL_WIDTH` / `PORTAL_HEIGHT` | 1.2 / 2.0 | размер проёма |
| `PORTAL_A_CENTER` / `PORTAL_B_CENTER` | — | позиции порталов |
| `SPAWN_POINT` | (-9, 1.2, 0) | точка спавна |

**Движение** — `src/physics.rs`:

| Константа | Значение |
| --- | --- |
| `PLAYER_RADIUS` / `PLAYER_LENGTH` | 0.35 / 0.9 |
| `MOVE_SPEED` / `SPRINT_SPEED` | 5 / 8 |
| `ACCELERATION` | 60 |
| `GRAVITY` / `JUMP_SPEED` | -22 / 8 |

**Порталы** — `src/portal.rs`:

| Константа | Значение | Смысл |
| --- | --- | --- |
| `TELEPORT_DISTANCE` | 0.55 | насколько близко к плоскости срабатывает переход |
| `EXIT_CLEARANCE` | 0.45 | насколько далеко вперёд ставится игрок на выходе |
| `TELEPORT_COOLDOWN` | 0.3 | пауза между переходами, сек |

> ⚠️ `TELEPORT_DISTANCE` и `EXIT_CLEARANCE` подобраны под капсулу `PLAYER_RADIUS = 0.35`
> и стену `WALL_THICKNESS = 0.2`. Если менять радиус игрока или толщину стены —
> эти два числа нужно пересчитать, иначе игрок либо застрянет в стене, либо
> проскочит портал.

Порталы поддерживаются только вертикальные: yaw извлекается через `EulerRot::YXZ`,
что предполагает чистый поворот вокруг `Y`.

## Производительность

- `[profile.dev.package."*"] opt-level = 3` в корневом `Cargo.toml` — зависимости
  оптимизированы уже в dev-профиле. Разница в FPS по сравнению с полностью
  debug-сборкой кратная.
- `cargo run --release` — ещё быстрее, но первая release-сборка занимает 5–10 минут.
- Портальная текстура рендерится в полном разрешении окна и обновляется каждый кадр:
  при большом окне это заметная доля нагрузки на GPU.

## Ограничения

- **Нет рекурсии** «портал в портале» — портальные камеры не видят экраны порталов
  (разные слои рендера).
- **Только вертикальные порталы** — наклонные и горизонтальные не поддержаны.
- **Один игрок** — телепорт и обзор завязаны на единственную камеру.
- **Путь к ассетам абсолютный** (`concat!(env!("CARGO_MANIFEST_DIR"), "/assets")`).
  Работает при `cargo run` и для собранного бинаря на этой машине, но если переносить
  `.exe` в другое место, папку `assets` нужно положить рядом и поменять путь.
- **HUD на английском**: у встроенного шрифта Bevy нет кириллических глифов.
